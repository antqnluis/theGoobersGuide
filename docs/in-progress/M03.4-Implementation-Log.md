### Deviations from the plan

1. **Guard fix (second migration).** Plan §2.2 restored `updated_by := old.updated_by` in the nested-update branch. That also undid the FK's `set null` on `updated_by`, so deleting an editor's account failed with `notes_updated_by_fkey`. The account-deletion test caught it. The branch now returns the row untouched: clearing a character link still leaves `updated_by` alone (the action changes only that column), and deleting an editor clears it. Plan §2.2 is corrected. It is a separate migration because the first was already applied locally; a fresh database applies both in order.
2. **Rolled-back tests cannot assert `updated_at` movement.** `private.set_updated_at` uses `now()`, which is fixed inside a transaction. The "deleting a linked character" test therefore checks the link, editor, body, and campaign, and the API test checks that `updated_at` advances (separate requests).
3. **Migration timestamps** are the real creation times; the plan's `2026111?xxxxxx` was illustrative.
4. `src/types/database.ts` is not regenerated yet. That is Phase 2.
