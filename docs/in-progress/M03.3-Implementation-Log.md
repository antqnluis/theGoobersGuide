### Deviations from the plan

1. **Weight above the bound reports `22003`, not `23514`.** Plan §9.1 expects weight 100,000 to fail with `23514`. The column is `numeric(7, 2)`, which cannot hold 100,000 at all, so PostgreSQL raises `numeric field overflow` (`22003`) before the check runs. The bound is enforced either way (99,999.99 is accepted, 100,000 and 99,999.999 are refused); `character_items_weight_check` still covers negatives. The tests assert `22003` for the upper bound. Frontend validation (Phase 3) enforces 0–99,999.99 with field messages, so users never see this code.
2. **Test-data safety.** The first draft of the currency-check test updated `character_sheets` without a `where`, which touched the real sheet inside a rolled-back transaction. It is now scoped to the fixture character, and the real sheet was verified unchanged afterwards.
3. **Migration timestamp** is the real creation time (`20261114190000`); the plan's `…160000` was illustrative.
4. `src/types/database.ts` is not regenerated yet. That is Phase 3.
