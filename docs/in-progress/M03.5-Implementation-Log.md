A fifth, `private.guard_adventure_participant_write`, keeps participant keys fixed and refuses participants on a main adventure for every write path, so the §4.2 invariant "no main adventure with participants" does not rely on `create_adventure` alone. Postgres-only, like the others.
2. **Spec type error.** `tsc -b` type-checks `e2e/`, and the first draft of the bypass test failed it; fixed with a cast. The full `test:local-supabase` run (139 passed) came before the fix; the build, lint, format check, and the adventures spec (20 passed) were re-run after it.
3. **Generated types** are left for Phase 2, as planned.
