## Overview and objectives

"Dice everywhere" means four things:

1. **Everywhere you are.** A dice control is always on screen inside a campaign: over the camp, over every open journal, and on phones. Outside a campaign (the galaxy selector) it still works, as private, unsaved rolls.
2. **Everything with a number.** On your own character sheet, every ability check, saving throw, skill, initiative, attack roll, and damage entry is a one-tap roll with the right modifier, advantage or disadvantage, and critical damage.
3. **Everything with dice in it.** Any dice notation in rendered text (`2d6 fire`, `1d8 + 3`, `d20`) becomes a roll chip: spells, features, sheet notes, attack notes, item descriptions, notes, adventure descriptions and updates. Nothing is rewritten in storage; chips are added when the text is displayed.
4. **Everyone sees it.** Rolls go to a shared campaign roll log that updates live for every current member. A roll can be made privately instead.

Rolls are made **by the database**, not the browser (D2), so a shared roll cannot be forged from the console.

M7 delivers:

1. A dice engine in `src/features/dice/`: notation parser, roll specification, client roller for private local rolls, and formatting.
2. `public.dice_rolls`, the `roll_dice` RPC with server-side randomness, RLS, retention, and Realtime publication.
3. A `DiceProvider` and `useDice()` hook that any component in the app can call to roll.
4. The dice tray: expression entry, quick dice, advantage and disadvantage, repeat, and the live campaign log.
5. Roll sources wired into the character sheet, and a `DiceText` renderer used by every free-text surface.
6. Optional: live HP, notes, and adventure updates over the same Realtime plumbing (D11).
7. Tests: unit (parser, distribution, extraction), integration against the local stack (RLS, randomness bounds, forgery attempts, Realtime visibility), and a mocked browser spec.

| **D2** | Where is the randomness? | **In Postgres**, inside `roll_dice`, using `extensions.gen_random_bytes` with rejection sampling. The client sends a structured spec, never results. Private local rolls outside a campaign use `crypto.getRandomValues` with the same rejection sampling. |

| **D5** | Who parses? | **The client parses text into a spec** (`terms` jsonb). The RPC validates the spec's shape and limits itself and **rebuilds the canonical expression** from it, so a stored expression always matches its dice. No text parser in SQL. |
| **D6** | Rolling as a character | A roll may name a character only if **you own it** (composite FK to `characters (id, owner_id)` plus the campaign). Sheet buttons appear only on your own sheets. Text chips on others' content roll as yourself with no character. |
| **D7** | Retention | Keep the **newest 300 rolls per campaign**; `roll_dice` deletes older ones in the same statement. The tray shows the newest 50 and loads more on scroll. No user deletion; the log is append-only. |
| **D8** | Rate limit | `roll_dice` refuses more than **20 rolls in 10 seconds per roller per campaign** (`P0001`, "Slow down"). Protects the log and Realtime from a stuck button or script. |
| **D9** | Critical hits | After an attack roll whose kept d20 is a natural 20, the result offers **"Roll critical damage"**, which doubles the dice count of every dice term of the linked damage (not the constants). A natural 1 and 20 are highlighted on any d20. |
| **D10** | Departure and deletion | A member who leaves keeps their rolls in the log, attributed by display name, until retention removes them. Deleting a character sets `character_id` to null on its rolls (`on delete set null (character_id)`). Deleting an account deletes that account's rolls. Deleting a campaign deletes its log. |
| **D11** | Realtime beyond dice | **Phase 6, optional:** live updates for `character_sheets` vitals, `notes`, and adventure rows over the same plumbing, replacing the refetch-on-focus comments. Can be cut to its own milestone (M7.2) without affecting dice. |

## 2. Database schema

### 2.1 `public.dice_rolls`

```text
dice_rolls
  id uuid pk default gen_random_uuid()
  campaign_id uuid not null → campaigns on delete cascade
  roller_id uuid not null → profiles on delete cascade
  character_id uuid null
      foreign key (character_id, campaign_id) → characters (id, campaign_id) on delete set null (character_id)
      foreign key (character_id, roller_id)   → characters (id, owner_id)    on delete set null (character_id)
  visibility text not null check in ('campaign','self')
  source text not null check in ('tray','ability','save','skill','initiative','attack','damage','text')
  label text null check (char_length(label) between 1 and 80)
  expression text not null check (char_length(expression) between 1 and 160)   -- canonical, rebuilt by the RPC
  terms jsonb not null      -- the validated spec (§5.1)
  dice jsonb not null       -- every face rolled, with kept/dropped flags, per term
  total integer not null
  created_at timestamptz not null default now()
  index (campaign_id, created_at desc)
  index (roller_id, campaign_id, created_at desc)     -- rate limit
```

### 2.2 `public.roll_dice(...)`

```text
roll_dice(
  p_campaign_id uuid,
  p_terms jsonb,
  p_visibility text default 'campaign',
  p_source text default 'tray',
  p_label text default null,
  p_character_id uuid default null
) returns public.dice_rolls
security definer, set search_path = ''
```

1. `auth.uid()` must be a current member of `p_campaign_id` (`42501` otherwise).
2. Validate `p_terms` (§5.1 limits) in `private.validate_dice_terms`; `22023` on any violation.
3. If `p_character_id` is given, it must be owned by the caller and belong to the campaign (the FKs enforce it too; the RPC gives a clear error first).
4. Rate limit (D8), counted from the roller index.
5. Roll each die with `private.random_int(1, sides)`: draw 4 bytes from `extensions.gen_random_bytes`, reject values in the biased tail, repeat.
6. Apply keep-highest/lowest, sum, build the canonical `expression`, insert, prune to 300 per campaign (D7), return the row.

`random_int` and `validate_dice_terms` live in `private`, `EXECUTE` granted to no client role (only reached through `roll_dice`).

### 2.3 Realtime

`alter publication supabase_realtime add table public.dice_rolls;` Postgres-changes delivery checks the subscriber's `select` policy per row, so private rolls and other campaigns never reach a client. `replica identity` stays default (inserts only).

## 3. RLS policies and authorization matrix

### 3.1 Grants

- `dice_rolls`: `select` to `authenticated`. **No** `insert`, `update`, or `delete` to any client role.
- `roll_dice`: `execute` to `authenticated` only.

### 3.2 Policy

`"Members read campaign rolls and their own private rolls"` — `for select to authenticated using (campaign_id in (select private.current_campaign_ids()) and (visibility = 'campaign' or roller_id = (select auth.uid())))`.

### 3.3 Matrix

| Action | Anon | Non-member | Member | Campaign owner | Roller |
| --- | --- | --- | --- | --- | --- |
| Read a campaign roll | — | — | R | R | R |
| Read a private roll | — | — | — | **—** | R |
| Roll in the campaign | — | — | yes | yes | — |
| Roll as a character | — | — | own characters only | own characters only | — |
| Insert, update, or delete a row directly | — | — | — | — | — |
| Receive a roll over Realtime | — | — | as Read | as Read | as Read |

**Explicit negatives to test:** a direct insert with a forged `total` is refused; a spec with 101 dice, `d1`, `d1001`, or 21 terms is refused; rolling as another player's character is refused; the campaign owner cannot read or receive a private roll; a removed member stops receiving rolls on an open subscription after reconnect and reads none.

## 4. Workflows and requests

### 4.1 Requests

| Action | Request |
| --- | --- |
| Roll in a campaign | `rpc('roll_dice', …)` → the returned row is prepended to the log cache |
| Load the log | `from('dice_rolls').select(...).eq('campaign_id', id).order('created_at', desc).range(...)` |
| Live log | `channel('dice:<campaign id>').on('postgres_changes', { event: 'INSERT', table: 'dice_rolls', filter: 'campaign_id=eq.<id>' })` → merge by `id` |
| Roll outside a campaign | client roller only, kept in component state, labelled "Not saved" |

### 4.2 Feel and failure

- The tray starts its rolling animation on press and settles on the returned faces (target under 300 ms locally). The roll is **never** shown with client-made numbers while the server call runs.
- On failure the pending roll shows the error and a **Retry**; nothing is added to the log. Offline shows "Can't reach the table — roll privately on this device?" which falls back to the local roller, clearly marked "Not saved".
- On subscription loss the tray shows "Live updates paused" and refetches the first page on reconnect.

### 4.3 Error copy

| Code | Copy |
| --- | --- |
| `42501` | "You're no longer in this campaign." |
| `22023` | "That roll is too big. Up to 100 dice and 20 parts." |
| `P0001` (rate) | "Slow down — too many rolls at once." |
| network | "Couldn't roll. Try again." |

## 5. Data shapes and rules

### 5.1 Spec (`diceTypes.ts`)

```ts
type DiceTerm =
  | { kind: 'dice'; sign: 1 | -1; count: number; sides: number; keep?: { mode: 'high' | 'low'; count: number } }
  | { kind: 'constant'; sign: 1 | -1; value: number }

type RollSpec = { terms: DiceTerm[] }          // what roll_dice receives as p_terms
type RollMode = 'normal' | 'advantage' | 'disadvantage'
```

Limits shared by client and server: 1–20 terms; `count` 1–100 and total dice ≤ 100; `sides` 2–1000; `keep.count` 1–`count`; constants within ±10,000.

### 5.2 Parser (`diceNotation.ts`)

- `parseDice(text): { ok: true; spec } | { ok: false; error; at }` — whitespace-tolerant, case-insensitive, `d20` means `1d20`, `d%` means `d100`.
- `formatSpec(spec)` — the canonical form the server also produces (`2d20kh1 + 5`), tested to match.
- `applyMode(spec, mode)` — rewrites a single `1d20` term; leaves other specs unchanged and reports it can't apply.
- `doubleDice(spec)` — critical damage (D9).

### 5.3 Extraction from text (`diceText.ts`)

- `findDice(text)` returns ranges of dice notation in prose. Matches need a `d` with a number of sides (`2d6`, `d20`, `1d8 + 3`); a bare `+5` in prose is never a match.
- Attack fields get dedicated helpers: `attackRollSpec(bonus)` reads "+5", "5", or "-1" as `1d20 + n`; `damageSpec(damage)` combines every dice segment ("1d8+3 slashing plus 2d6 fire") into one spec with a per-segment label shown in the breakdown. Unparseable fields show no button, never an error.

| Where | What rolls | Source |
| --- | --- | --- |
| Tray | Typed expressions, quick d4/d6/d8/d10/d12/d20/d100, repeat last, advantage/disadvantage | `tray` |
| Own sheet: abilities | Ability check: `1d20 + modifier` | `ability` |

Every roll carries a label built from its source ("Stealth check", "Longsword damage", "Fireball — 8d6"), so the shared log reads like a table conversation.

**Modifiers on any d20 source:** a press rolls normally; a small menu (or long-press on touch) offers advantage, disadvantage, and private. Desktop shortcuts: Shift-click advantage, Alt-click disadvantage.

### 6.3 Tray behaviour

- A fixed button bottom-right, above the camp and journals, with a count badge for unseen rolls by others. Opens a side sheet on desktop and a bottom sheet on phones (16px gutters, no horizontal scroll).
- Keyboard: the tray opens from its button, or with `R` when focus is not in a text field. `Esc` closes it, and focus returns to the opener.
- Results announce through a polite live region ("Mira rolled Stealth: 17"); others' rolls announce only while the tray is open, so the screen reader isn't flooded.
- Reduced motion: no tumbling animation, results appear directly.
- The log groups by minute, shows the roller's display name and character, the expression, each face (dropped dice struck through, natural 1/20 marked), and the total.

### 6.4 Caching

`['dice', campaignId, 'log']` infinite query, newest first. Realtime inserts and own RPC results merge by `id` (no duplicates when both arrive). Leaving the campaign removes the query and closes the channel.

## 7. Membership departure, rejoin, and lifecycle

Follows D10. A departed member's channel is closed by the client on leaving; on any other device, Realtime stops delivering once RLS no longer matches. On rejoin, the member reads the log as it is now (their own old rolls included, if not pruned).

## 12. Risks and edge cases

### Risks

- **Realtime and RLS cost.** Postgres-changes evaluates the select policy per subscriber per row. At friend-group scale this is negligible; the campaign filter keeps it so. Broadcast channels would be the fallback if it ever isn't.
- **False positives in text.** Prose like "3d printer" could become a chip. The matcher requires a number of sides and a word boundary, and unit fixtures pin the known cases.
- **Free-text attack fields.** Some imported sheets will have bonuses like "+5 to hit (finesse)". Unparseable fields show no button; the text chip still catches any dice in them.
- **Latency.** Server rolls add a round trip. The animation hides it locally; on a slow network the pending state must be clear and never show fake numbers.
- **Scope.** Phase 6 touches three existing features' caches. It is optional and separable so it never blocks dice.

### Edge cases covered

A roll during campaign departure (RPC refuses, tray shows the 42501 copy); a character deleted mid-roll (FK nulls it); the same roll arriving from the RPC and Realtime (merged by id); a removed member with the tray open (subscription stops matching, next fetch is empty, tray closes on the membership change); two tabs rolling at once (both appear, ordered by `created_at`); a roll with only constants (allowed, total is the constant, flagged "no dice" in the log).
