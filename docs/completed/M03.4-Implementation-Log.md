### Deviations from the plan

1. **Guard fix (second migration).** Plan §2.2 restored `updated_by := old.updated_by` in the nested-update branch. That also undid the FK's `set null` on `updated_by`, so deleting an editor's account failed with `notes_updated_by_fkey`. The account-deletion test caught it. The branch now returns the row untouched: clearing a character link still leaves `updated_by` alone (the action changes only that column), and deleting an editor clears it. Plan §2.2 is corrected. It is a separate migration because the first was already applied locally; a fresh database applies both in order.
2. **Rolled-back tests cannot assert `updated_at` movement.** `private.set_updated_at` uses `now()`, which is fixed inside a transaction. The "deleting a linked character" test therefore checks the link, editor, body, and campaign, and the API test checks that `updated_at` advances (separate requests).
3. **Migration timestamps** are the real creation times; the plan's `2026111?xxxxxx` was illustrative.
4. `src/types/database.ts` is not regenerated yet. That is Phase 2.

### Deviations from the plan

1. **A conflict carries the latest note.** Plan §6.1 says `saveNote` "re-reads on zero rows to tell conflict from unavailable". It now throws `NoteConflictError` holding the re-read note, so "Load latest" needs no second request, and the hook adopts it into the caches.
2. **Results instead of booleans.** `create`, `save`, and `changeVisibility` resolve to `{ ok: true, note }`, `{ ok: false, reason: 'conflict', latest }`, or `{ ok: false, reason: 'unavailable' | 'failed' }`. The editor needs to know a conflict from other failures, and `create` needs the new note to open it. `remove` resolves to a boolean (true when the note is gone, including already unavailable).
3. **New error code `note_campaign_unavailable`.** A `42501` on insert maps to it, so the surface shows "You can no longer add notes to this campaign." and the hook refreshes the campaign and roster, as the character actions do.
4. **Unavailable also refreshes the campaign.** On `note_unavailable` or `note_campaign_unavailable`, the hook invalidates the campaign detail and roster keys, so a removed member reaches the camp's existing "campaign not available" handling.
5. **Attribution takes the roster rows** (`profile_id`, `username`, `display_name`) already loaded for the Party, not a new query.

- **List:** "New note", a title filter (from the first note), and two groups, Shared with the campaign and Only you, each newest edit first. Each row shows the title, author ("You", a name, or "A former member"), "Edited by … , 2 hours ago", and the linked character. Loading, error with retry, empty, and no-match states.
- **Read:** title, standing chips (an icon and text for shared or private), the linked character, the text with line breaks kept, and who wrote and last edited it. Any member edits a shared note. Only the author shares it, makes it private (after "Members will no longer see **{title}**, including their edits."), or deletes it (after a confirmation).
- **Write:** title, text with a counter from 18,000 characters, an optional character link, and, for a new note, who can read it. A stale save keeps the text and offers **Load latest** (after a confirmation) and **Save mine anyway** (against the latest version). A note that has gone keeps the text on screen, blocks saving, and offers a way back. A link to a character the writer cannot see is kept, not dropped.
- **Guards and focus:** closing the journal, going back, or closing the tab with unsaved text asks first. Focus goes to the title when the editor opens, to the note's heading when it loads, back to the note's row from the note, and to the confirm button when a confirmation opens.
- **Loading:** the list loads when the Notes destination is first opened and refreshes on each later opening and on window focus.
- **Delete-campaign copy:** "…member list, notes, and every player's characters, character sheets, and inventories will be removed. This can't be undone." (M03.8 had not changed the sentence, so the plan's wording slotted in.)
