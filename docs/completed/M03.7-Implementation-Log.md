### Contract Phase 2 must match in SQL

1. **Canonical expression** (`formatSpec`): terms joined by single spaces; first term has a `-` prefix with no space if negative; later terms are ` + x` or ` - x`; dice are `{count}d{sides}`, with `kh{n}` or `kl{n}` appended when keeping; always an explicit count (`1d20`, never `d20`). Example: `-1d4 - 2 + 2d20kh1`.
2. **Random draw:** one uniform unsigned 32-bit integer per attempt (4 bytes from `gen_random_bytes`, big-endian). With `limit = floor(2^32 / sides) * sides`, a draw below `limit` gives `draw % sides + 1`; otherwise draw again.
3. **Keep ties:** faces are ordered by value (descending for high, ascending for low), earliest die first on a tie; the first `keep.count` are kept.
4. **`dice` column shape:** an array aligned with `terms`; each entry is an array of `{ "value": n, "kept": bool }` in roll order, empty for a constant term. `total` is the sum of signed kept faces plus signed constants.
5. **Limits:** as `diceLimits`; also total dice across terms ≤ 100. The spec's `keep.count` must be between 1 and the term's `count`.

### Decisions made while building

1. **Advantage rewrites one `1d20` among other terms.** `applyMode` needs exactly one plain, positive `1d20` and leaves other terms alone, so `1d20 + 1d4 + 2` (Bless) works. Anything else reports "can't apply".
2. **Crit doubling also doubles `keep.count`,** so `4d6kh3` becomes `8d6kh6` (every die rolled again).
3. **Bare `k` is not accepted;** keep needs `kh` or `kl` and a count, as in the plan.
4. **Flat damage has no button.** `damageSpec("5 bludgeoning")` is null because it has no dice segment, as the plan says (dice segments only).
5. **A zero attack bonus** (`+0`) rolls plain `1d20`.

### Deviations and notes

1. **Error codes.** `roll_dice` raises `42501` with message `not_a_member` (left, removed, or never a member) or `character_unavailable` (not your character in this campaign); `22023` with `dice_terms_invalid` or `dice_roll_invalid` (bad visibility, source, or label over 80 characters); and `P0001` with `dice_rate_limited`. The client must read the message to tell the two `42501` cases apart (the plan's copy table keyed only on the code).
2. **Blank labels** are stored as null (the RPC trims and nulls an empty label), so the table's 1–80 check never sees an empty string.
3. **`created_at`** is set from `clock_timestamp()` in the RPC (the column default stays `now()`), so rolls in one transaction order correctly and the rate window is exact.
4. **Realtime subscription timing.** `SUBSCRIBED` arrives before the server registers the row filter; a roll sent immediately can be missed. The spec waits one second after subscribing. Phase 3's `useDiceLog` should refetch the first page after it reports `SUBSCRIBED` so no roll is lost in that gap.
5. **Import path.** The e2e spec imports `formatSpec` and `parseDice` from `src/features/dice/`, which `tsconfig.node.json` type-checks under Node resolution; `diceNotation.ts` therefore imports `./diceTypes.ts` with its extension (as other `src` files already do).

### Deviations and notes

1. **Refetch on event, not row merge.** The plan said "cache merges". Notes, adventures, and sheets are read with joins and optimistic-concurrency stamps, and children (objectives, updates) have no campaign column, so merging a payload would duplicate server logic. An event instead marks the read stale and the query refetches it. Dice rolls, which are self-contained rows, still merge by id.
2. **No delete events.** A delete event carries only the primary key and is not checked against the subscriber's policy, so the app subscribes to inserts and updates only. Removals, and rows that stopped being readable (a shared note made private), arrive through each query's refetch on focus, which is kept.
3. **Unfiltered tables.** `character_sheets`, `adventure_objectives`, and `adventure_updates` have no `campaign_id`, so every row the player may read arrives (other campaigns' too) and only reads the client already holds are refetched; the list is refetched for an objective only when it already shows that adventure.
4. **Edits in progress.** A live change refetches like a focus refetch does today: open editors keep their drafts and meet the existing conflict handling on save.
5. **No new UI.** There is no connection indicator for the campaign channel; the dice tray still shows its own "Live" and "paused" line.
